# Issue 179 CPU persistence endurance plan v1

This is a predeclared engineering verification dose. It is not a new comparison
of scientific policy superiority. It uses already public tiny-model fixtures;
there is no protected prospective holdout or paid resource authorization.

Run two isolated cohorts of the unchanged public CPU autonomy plan: nine programs
per cohort, three seeds × fixed/heuristic/adaptive policy, three sequential native
45-operation cycles per program and four optimizer updates per cycle. Totals are
18 programs, 54 cycles, 2,430 native operation completions, 216 actual optimizer
updates and another 216 independently cold-reexecuted updates. The existing
first-attempt, pre-update process failure remains in each program; all 18 failed
predecessors and their safe bounded repairs must survive.

An immutable source installation and a separately retained precommitted file
inventory bind the whole framework/configuration, including storage, snapshot,
witness and verification implementations. Keep every failed attempt. Source
changes during a cohort invalidate that attempt. A final report records accepted
source commit/tree identities, environment, elapsed time and all attempt paths.

During every program, a distinct process repeatedly opens read-only application
repositories and performs coherent SQL read transactions, periodic full integrity
checks and monotone record-count checks. After each program, stop the inspector,
require workers settled/reaped, take a complete sealed campaign snapshot, restore
at the original logical path while quarantining the original root under the
external fence, then reconstruct all repository objects. Compare the complete
ordered record digest, operation IDs, sequence order, publication counts, artifact
hashes and retained checkpoint identities before/after restoration. Restart the
already completed program in a fresh process: the result and committed record
set must remain identical, without duplicate optimization or assessment.

Cold-read each restored program in another new process. Recompute 45-operation
traces, policy/parent decisions, all development and final tiny-model inference,
NLL, exact answers, failure diagnosis, lineage and memory. Reexecute every fixed
optimizer job and require tensor-exact adapter, optimizer, scheduler and RNG
state reproduction. Require all nine consumed/completed final publication pairs
in each cohort and no missing completion. Keep sealed snapshots, quarantine
roots, raw process logs, inspector outputs and per-program verification receipts.

Acceptance is conjunctive; a record count or elapsed duration alone does not pass.
Each cohort should reach the authentic campaign's tens of thousands of state
records, substantially exceeding the previous 2,400-record synthetic check.
Separate real process-kill tests cover transaction/acknowledgement/reconciliation,
backup and restore interruptions, stale rollback, corrupted state and competing
controllers. Process kills do not demonstrate physical power-loss durability.

The available overlay filesystem can validate only the declared container/host-
lifetime rehearsal profile. Operator-managed retained ext4/xfs/btrfs deployment
still requires validation on its real mount and separate backup/witness retention.
No successful cohort establishes the cause of historical SQLite corruption or
cross-host, whole-host rollback, hardware or path-relocation safety.
