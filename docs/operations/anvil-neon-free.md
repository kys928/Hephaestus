# Anvil hosted research ledger

Use the existing Neon account on the Free plan. Create a dedicated project named `hephaestus-anvil` and record its project identity, region and PostgreSQL version without any connection string. Use PostgreSQL 17 to match qualification. Keep operational queue, artifacts and independent restore evidence outside the runtime credential.

1. Sign in to [Neon Console](https://console.neon.tech). Open the account's project dashboard. Create `hephaestus-anvil` on Free if it is absent. Keep the default owner connection private.
2. From the immutable integration commit, run `PYTHONPATH=src python scripts/anvil_neon_bootstrap.py emit-sql diagnosis-planner-v1`. Run the emitted SQL as the project owner in Neon SQL Editor. It creates only the Anvil schema, restricted runtime role and the single investigation's epoch row. Use a direct verified-TLS connection and the owner login in a private terminal if using psql instead.
3. Complete the credential handoff in a private local terminal. With `gh` signed into the authorized GitHub account and `psycopg[binary]>=3.2,<4` installed, run `python scripts/anvil_neon_register_runtime.py`. Supply the direct owner connection string to the hidden prompt. The helper checks the pinned project endpoint and restricted role, generates a runtime password, enables login, stores only the runtime DSN in GitHub, then checks the login. Neon requires plaintext for password initialization over verified TLS, so the standard psql hidden `\password` command is unsuitable because it sends a pre-hashed value.
4. Verify only the secret name `ANVIL_POSTGRES_DSN` in [Hephaestus Actions secrets](https://github.com/kys928/Hephaestus/settings/secrets/actions). Keep both connection strings out of chat, source control and workflow logs. If the helper says the secret already exists, qualify that secret before attempting rotation.
5. In an authorized runtime where the configured secret is injected, run `PYTHONPATH=src python scripts/anvil_neon_bootstrap.py verify-runtime diagnosis-planner-v1`. Verify named-role login, certificate verification, append-plus-read grants, the absence of runtime update/delete and epoch privileges, and the exact initial epoch. Preserve only boolean evidence.
6. For hosted qualification, use a disposable qualification investigation. Record independently accepted IDs and the frontier, reopen through a fresh connection, rotate its epoch using the separate owner session, and prove stale completion is rejected. Retain an encrypted, independently controlled dump plus the digest and accepted frontier. Restore it into a separate PostgreSQL instance and compare contribution records and the expected frontier before authorizing scientific use. A Neon branch alone does not provide independent backup.

The scoped runtime login is for the trusted admission service. It can insert raw ledger rows, so the GPU model process receives neither this DSN nor the owner credential. The per-slot GPU receipt crosses into the controller by the existing signed admission route.
