### Custody and duplication

The independently read HF export manifest SHA-256 is `129d690ef9ae24ef141fbb0c1ce48280f033b33f03b691073c20231d16677638`. The sorted evidence path/size/SHA-256 digest shared by Czech, Global and that manifest is `ee65857c7da12b81fee33b0f981b4944248f7571c645023c555154a22508b03d`. The manifest declares verified uploads for 8,113 evidence files (607,265,483 bytes), 869 model objects (19,976,531,570 bytes) and four training-data objects (173,077,196 bytes). It contains no exact length-and-SHA match for any of the five certified adapter archives. Authenticated manifest comparison establishes backup coverage at the manifest level. A current independent reread of the HF backup objects and a complete offline model cache are open.


- The Czech volume supplies the independently verified original adapter bytes, source inventory and retained historical run objects. The mounted Global volume is a read-mostly copy for portable artifacts. The authenticated HF export is a separate provider with bounded curated coverage.
- The HF manifest's five-archive coverage gap and the unverified offline model snapshots require retaining the original copies. ETags, matching object counts, catalog revisions and configurable volume names are insufficient to authorize deletion, role activation or a state cutover.
- The two historical Global source readers are byte-identical. Both layouts now go through one certified materialization mechanism with the regional and remote paths. The provider continues to use one lifecycle transport. Historical one-shot launchers remain preserved at their original commits for external caller and reproduction checks.
