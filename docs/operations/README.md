# Operations

These runbooks distinguish safe inspection and CPU validation from actions that require a separately approved compute, storage or production authorization.

1. [Developer quickstart](developer-quickstart.md): clean checkout, install, CPU checks, demo and replay inspection.
2. [Run safety](run-safety.md): experiment admission, resource/credential boundaries, incident response and paid execution.
3. [Release and rollback](release-checklist.md): exact PR/CI review, the accepted branch-protection waiver, history preservation and recovery.
4. [Supported execution](supported-execution.md): real CPU research walkthrough, executable actions, excluded transitions, Ardor limits and inactive scaffolds.
5. [Remediation ledger](remediation-ledger.md): all eleven audit findings, exact ordinary merges, regressions and CI.
6. [Staged failure recovery](staged-failure-recovery.md), [checkpoint identity](checkpoint-identity.md), [execution ownership](execution-ownership.md) and [legacy launch boundary](legacy-execution.md).
7. [Prospective custody](prospective-custody.md), [strict scoring](answer-scoring.md), [structured supervision](structured-supervision.md), [training dose](training-dose.md) and [configuration](production-configuration.md).
8. [Campaign storage health](sqlite-campaign-health.md): closed readers, integrity gates, consistent snapshots and the unresolved #179 investigation.

Current terminal/console reference documentation remains available at [local app quickstart](../local_app_quickstart.md) and [operator console](../operator_console.md). These are **local bounded inspection tools**, not an unrestricted experiment-launch UI.

The maintained GitHub Actions inventory is documented in [issue #151 workflow retirement](../integration_notes/151-active-workflow-retirement.md). Historical one-off paid launchers should be read from source history only, not restored or dispatched with previously spent approval.
